# Архитектурные решения

Короткий журнал решений: что выбрали, почему и какие были альтернативы.

## 001. Модульный монолит

**Решение:** одно ASP.NET Core приложение, AI-возможности разделены по модулям в папке `Modules/`.

**Почему:** у проекта один разработчик и один деплой; микросервисы добавили бы сетевые вызовы, отдельные CI и наблюдаемость без пользы. Границы модулей позволяют выделить сервис позже, если появится реальная причина.

## 002. Секреты только вне репозитория

**Решение:** ключи LLM-провайдеров читаются из конфигурации (`OpenAI:ApiKey`), локально через user-secrets, в Cloud Run через переменные окружения или Secret Manager.

**Почему:** утечка ключа через публичный репозиторий означает прямые расходы и компрометацию аккаунта.
